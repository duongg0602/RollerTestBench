# CAN Communication Framework on STM32F103

## 1. Requirements

- STM32CubeIDE
- UART peripheral with interrupt enabled

## 2. How to use

### 2.1 Step 1: add the framework to your project

Add the following files into the project:

```
Core/
├── Inc/
│   └── CAN.h
└── Src/
    └── CAN.c
```

### 2.2 Step 2: CubeMX Configuration (set .ioc)

Configure the MCU clock normally according to the target application.

#### CAN

Configure one CAN peripheral for communication.

**Configuration:**

```
Prescaler           : 2
Time Quanta 1       : 12
Time Quanta 2       : 3
ReSynchronization   : 1
```

Enable the corresponding CAN interrupt in:

```
NVIC → USB high priority (CAN TX ISR) & USB low priority (CAN RX ISR)
```

### 2.3 Step 3: main.c config

**Include the lib**
```c
#include "CAN.h"
```

**Keep the peripheral initialization generated by CubeMX.**

**Call `CAN_Config()` right after CubeMX's CAN init, before the main loop:**

```c
int main(void)
{
    HAL_Init();

    SystemClock_Config();

    MX_GPIO_Init();
    MX_CAN_Init();
    MX_TIM3_Init();

    uint32_t IDList[] = {0x040, 0x070, 0x403, 0x405, 0x406};   // ví dụ Node 0x01
    CAN_Config(IDList, sizeof(IDList));

    HAL_TIM_Base_Start_IT(&htim3);

    while (1)
    {
        /* Application code */
    }
}
```

| Call | Meaning |
|---|---|
| `CAN_Config(NULL, 0)` | Accept every ID on the bus (used by the gateway/node0) |
| `CAN_Config(idList, count)` | Accept only the given IDs (hardware filter, up to 14 IDs, one filter bank per ID) |

## 3. Sending a message — `CAN_Send_IDxxx()`

Each of the 19 messages has its own **TX staging struct** (`TX_IDxxx`) and its own send function. Fill the struct, then call the matching function — no byte packing needed.

```c
TX_ID406.WheelSpeed = 1200;
TX_ID406.PulsePerRevolution = 60;
TX_ID406.Error_code = 0;
CAN_Send_ID406();
```

> **Important:** always write to `TX_IDxxx`, never to `Message_IDxxx`. `Message_IDxxx` is reserved for received data — it is written only by the RX interrupt. Mixing the two risks the ISR overwriting data you're in the middle of sending, or you accidentally sending stale received data back out.

## 5. Message ID RX for each node

| Node | Function | ID RX (IDList) | Bank number |
|---|---|---|---|
| `0x00` | `GUI` | `0x401, 0x411, 0x421, 0x431, 0x402, 0x412, 0x403, 0x404, 0x405, 0x406, 0x407` | `11` |
| `0x01` | `Motor control` | `0x040, 0x070, 0x403, 0x405, 0x406` | `5` |
| `0x02` | `Generator control` | `0x080, 0x404, 0x407` | `3` |
| `0x03` | `Motor torque` | `0x0C0` | `1` |
| `0x04` | `Generator torque` | `0x100` | `1` | 
| `0x05` | `Brake torque` | `0x200` | `1` | 
| `0x06` | `Wheel speed` | `0x180` | `1` | 
| `0x07` | `Roller speed` | `0x1C0` | `1` | 


TO OBTAIN RECEIVED DATA:

Dữ liệu nhận được nằm sẵn trong các biến toàn cục Message_IDxxx (mỗi ID một struct, luôn giữ giá trị mới nhất):

C
float motor_volt = (int16_t)Message_ID411.Motor_volt * 0.01f;

Các biến chung:

C
CAN_RX          // header frame vừa nhận: StdId, DLC
CAN_rx_data     // 8 byte thô của frame vừa nhận (bị ghi đè mỗi frame)
Rx_count        // số frame đã nhận
Tx_count        // số frame đã gửi xong (Mailbox0)
